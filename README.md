# branchkit-gen

Codegen and validation for [BranchKit](https://branchkit.dev) plugin manifests.

- **Generate** typed action param types from your `plugin.json`'s `action_types` block (`actions_gen.go`, `actions_gen.ts`, `actions_gen.py`), and typed record shapes for the collections it reads (`collections_gen.*`).
- **Validate** your `plugin.json` against the manifest contract — same checks the BranchKit runtime applies, runnable in CI before you ship.

## Install

```bash
go install github.com/branchkit/branchkit-gen@latest
```

Or clone and build locally:

```bash
git clone https://github.com/branchkit/branchkit-gen.git
cd branchkit-gen
go build -o branchkit-gen .
```

## Usage

### Generate

```bash
# Generate for a single plugin
branchkit-gen --plugin ./my-plugin

# Generate for every subdirectory containing a plugin.json
cd plugins && branchkit-gen --all
```

The tool reads the plugin's layout to decide which languages to emit and where. The rules match what `branchkit-cli dev init` scaffolds:

| Language | Detected by | Written to |
|---|---|---|
| Go | `src/go.mod` | `src/actions_gen.go` |
| TypeScript | `package.json` (plugin root or `src/`) and an entry module (`src/index.ts`, `index.ts` or `src/main.ts`) | beside the entry module, e.g. `src/actions_gen.ts` |
| Python | `main.py` (plugin root or `src/`), or a `run` command starting with `python` | beside `main.py`, e.g. `actions_gen.py` |

`src/package.json` alone (TypeScript) and `src/pyproject.toml` alone (Python) are also recognised, writing into `src/`.

Every generated file starts with a header naming the command that regenerates it:

```go
// Code generated by branchkit-gen from plugin.json `action_types`. DO NOT EDIT.
// Regenerate from the plugin directory: branchkit-gen --plugin .
```

### Validate

```bash
# Validate the plugin.json in the current directory
branchkit-gen validate

# Validate a specific plugin directory
branchkit-gen validate ./my-plugin

# Validate every subdirectory containing a plugin.json
branchkit-gen validate --all

# JSON output for CI
branchkit-gen validate --json ./my-plugin

# Skip the source-analysis drift checks
branchkit-gen validate --no-drift ./my-plugin
```

`validate` runs two layers of checks. Errors exit non-zero so CI can gate on a clean run.

**Manifest checks** mirror the rules the BranchKit runtime applies at plugin load time: `id` and `action_prefix` format, `min_api_version` semver, `settings_tabs` key safety, `dispatch_via` consistency, well-formed `action_types` (valid `field_type`, `enum` declarations carry `enum_values`), and informational notes for unrecognized top-level fields.

**Drift checks** (Go plugins only, today) compare the plugin against an OpenRPC spec embedded in the binary at build time:

- Each capability you declare must exist in the public capability list — typos here only surface at install time without `validate`.
- For every `*.Call("method.name", …)` callsite in your `src/` tree, the validator looks up the method in the spec and reports:
  - **error** if the method's `x-removed-in` ≤ your `min_api_version` (the call will hard-fail at runtime)
  - **error** if the method's `x-since` is greater than your `min_api_version` (you'd run on an older actuator that doesn't have it)
  - **warn** if the method is currently deprecated (plan a migration)
  - **info** if the method isn't in the platform spec at all (typo, or a plugin-to-plugin call)

Static analysis is best-effort — runtime-computed method names slip through. TypeScript drift detection is not yet implemented; pass `--no-drift` if you only want manifest checks.

## Example

Given this `plugin.json`:

```json
{
  "action_prefix": "music",
  "action_types": {
    "play": {
      "label": "Play Track",
      "fields": [
        { "key": "uri", "field_type": "string" },
        {
          "key": "mode",
          "field_type": "enum",
          "enum_values": ["shuffle", "repeat", "once"],
          "required": true
        }
      ]
    },
    "pause": { "label": "Pause" }
  }
}
```

Running `branchkit-gen --plugin .` in a Go plugin produces `src/actions_gen.go`:

```go
// Code generated by branchkit-gen from plugin.json `action_types`. DO NOT EDIT.
// Regenerate from the plugin directory: branchkit-gen --plugin .

package main

import "github.com/branchkit/plugin-sdk-go"

// PauseParams is the params shape for action "music.pause (Pause)".
type PauseParams struct {
}

// HandlePause registers a typed handler for action "music.pause (Pause)".
func HandlePause(p *branchkit.Plugin, fn branchkit.ActionHandlerFunc) {
	p.HandleAction("music.pause", fn)
}

// PlayMode is a generated enum type.
type PlayMode string

const (
	PlayModeShuffle PlayMode = "shuffle"
	PlayModeRepeat  PlayMode = "repeat"
	PlayModeOnce    PlayMode = "once"
)

// PlayParams is the params shape for action "music.play (Play Track)".
type PlayParams struct {
	Uri  *string  `json:"uri,omitempty"`
	Mode PlayMode `json:"mode"`
}

// HandlePlay registers a typed handler for action "music.play (Play Track)".
func HandlePlay(p *branchkit.Plugin, fn func(PlayParams, *branchkit.OnActionRequest) (any, error)) {
	branchkit.HandleActionTyped(p, "music.play", fn)
}
```

Your handler registers through the generated function, so the action string is never spelled by hand and the params arrive typed:

```go
HandlePlay(plugin, func(p PlayParams, _ *branchkit.OnActionRequest) (any, error) {
	switch p.Mode {
	case PlayModeShuffle:
		// ...
	}
	return nil, nil
})
```

## Supported field types

| `field_type` | Go | TypeScript | Python |
|---|---|---|---|
| `string` (default) | `string` / `*string` | `string` | `str` |
| `int` | `int` / `*int` | `number` | `int` |
| `number` | `float64` / `*float64` | `number` | `float` |
| `boolean` | `bool` / `*bool` | `boolean` | `bool` |
| `string[]` | `[]string` | `string[]` | `list[str]` |
| `enum` (with `enum_values`) | typed `string` + `const` block | literal union | `Literal[...]` |
| `object` (with nested `fields`) | `json.RawMessage` | `unknown` | `Any` |
| `json` (escape hatch) | `json.RawMessage` | `unknown` | `Any` |

Non-required fields are pointer-wrapped in Go, optional (`?`) in TypeScript and `NotRequired` in Python.
